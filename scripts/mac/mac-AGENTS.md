# This Mac (agents read this first)

The owner's own desktop Mac, reached with `ssh mac` from a dev box. Installed and kept current by
ejc3/aws `scripts/mac-setup.sh`; the section marked "found" below is written by `mac-agents-md`
from what is on the machine now (hourly, and at every setup). Do not edit this file by hand:
change `scripts/mac/mac-AGENTS.md` in ejc3/aws.

## Rules

- **Builds go to the Mac mini** (`ssh mini`) unless the task needs this Mac: its attached phone, the
  owner's signed-in browser, or its login keychain. Big build products go under
  `/Volumes/Scratch/<project>/` (check it is mounted), never in the home directory.
- **The desktop lease:** take it (`mac-lease run NAME -- CMD`) before driving the screen or
  relaunching an app; `peekaboo` waits while another session holds it.
- **Signing:** run the signing step through `mac-gui [--timeout S] -- CMD`, which reaches the login
  keychain; plain SSH gets `errSecInternalComponent`.
- Act only in windows you opened; change no account, payment or setting the owner did not ask for.
- **Peekaboo 4:** screenshot with `peekaboo see --no-elements --path FILE` (`image` was removed), keys with
  `peekaboo press cmd+n --app NAME --foreground` (`hotkey` was removed); app switches and raw key presses are refused
  without `--foreground`.

## Testing on the attached iPhone

The phone below is on USB with Developer Mode on, signed in to the owner's account. **UI Automation
is on** (the owner turned on Settings › Developer › Enable UI Automation on 2026-11-27; ejc3/aws#1062), so UI
tests run on it. It **lapses whenever the phone passcode-locks**, Auto-Lock included (three cycles seen on
2026-11-27): the phone then shows "Enter iPhone Passcode for 'XCTest' — Enable UI Automation", and unlocking the
phone does not bring it back; only typing the passcode at that prompt does. While it is lapsed, `xcodebuild test`
fails about a minute in with "Timed out while enabling automation mode" and runs no test. Say so to the owner
once and stop; do not change the setting yourself. Never lock the phone yourself (Device Hub's Controls › Lock
does): only the owner can unlock it. A
LaunchAgent on this Mac (`dev.dolphinlabs.uia-watch`) runs one short UI test every 2.5 hours. It logs each run
to `/Volumes/Scratch/dolphin-maps/uia-watch/status.log` and adds a line to `ALERT` beside it when the setting
lapses, so read that log before blaming a failure on your own test.

The phone refuses to remove apps ("Uninstall prohibited"): `devicectl device uninstall app` fails. Don't count
on removing what you install. A development build of an app replaces the TestFlight build with the same bundle
id until TestFlight installs it again.

A check that needs a real device (a universal link tapped, a sign-in sheet, push, the
camera) is yours to run: never hand the owner a step this phone can do. The Mac mini has phones
too; its `~/AGENTS.md` says how to build and sign there.

Limits on that phone: work only in the app under test, TestFlight and the system prompts it raises. No
purchases, no payment or Apple Account sheets, no settings outside the app's own, and nothing in the
owner's other apps.

- `xcrun devicectl device info apps` does not list App Store or TestFlight apps, not even with
  `--include-all-apps`. An app missing from it proves nothing.
- Use the build testers run first: the project's TestFlight build, installed through TestFlight
  on the phone. A development build signed here is covered by the "Agent wildcard dev MacBook
  iPhone 13" profile.
- A phone asleep with no passcode asked for (`devicectl device info lockState`) wakes in a UI test
  with `XCUIDevice.shared.press(.home)` and a swipe up on the springboard; only a passcode needs
  the owner.
- Open a link in the app with `XCUIApplication(bundleIdentifier:).open(url)`;
  `XCUIDevice.shared.system.open(url)` sends an `https` URL to the browser, never through universal
  links. A sign-in sheet's page belongs to `com.apple.SafariViewService`; system prompts to
  `com.apple.springboard`. Pass values to the runner as `TEST_RUNNER_<NAME>` in `xcodebuild`'s
  environment.
